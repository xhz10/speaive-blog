# 架构评审与重构建议

## 结论

值得做局部重构，暂时没有全面推倒重写的理由。现有代码已经具备正确的分层依赖、纯 Java 领域模型、用例端口与真实数据库测试。主要问题是业务规模增长后少数服务职责过多，以及缺少中文阅读地图；不是“没有把文件夹命名成 DDD”。

本次对照当前源码及近期 Git 历史检查。`336fb55` 的创作闭环和 `9db9c48` 的小说工作台扩展解释了服务职责增长；最近一些提交信息只有“提交代码”或“支持新功能”，不足以快速定位业务意图。后续提交宜说明具体触发行为与结果，不必另建复杂流程。

## 已经做对的部分

| 观察 | 代码证据与意义 |
| --- | --- |
| 依赖向业务内层收敛 | application 直接依赖 domain；数据库/SDK 位于 infrastructure；Controller 调用 input port |
| 不是只有字段的实体 | Post、Comment、AgentProfile、Inspiration 等通过有业务含义的方法维护规则 |
| 乐观并发有数据库保护 | PostChange 携带旧快照，仓储使用 CAS；同事务写主记录与修订 |
| AI 与数据库事务分离 | 模型等待在短事务之外，避免长时间占用连接与锁 |
| DTO、PO 与业务对象分开 | 边界采用 MapStruct 编译生成映射，减少运行时隐式复制 |
| 架构有可执行约束 | ArchUnit、领域单测、应用假端口、PostgreSQL Testcontainers、HTTP 集成测试 |

## 本次实际完成的整理

- 把应用层重复的回复资格判断收回 `Comment.ensureCanReceiveAiReply`，预检查与回复创建复用同一规则。
- 把 `transition(id, true/false)` 拆成可直接阅读的发布、隐藏动作，去掉无意义的 `requiredPost(..., true)` 参数，改用明确的 `requiredPostById`。
- 批量生成建立独立 `CommentBatchApplicationService`，虚拟线程放在出站适配器，不继续扩张原评论服务，也不向领域注入并发框架。
- 访客统计单独建立 analytics 业务与用例边界，公开采集和管理员读取有不同 Controller；统计数据不混入公开文章返回值。
- 为生产枚举及其成员增加中文说明；补充核心类型、端口、关键事务流程注释，并建立架构、业务状态、请求流程文档。

| 中 | `CreativeWorkspaceApplicationService` 同时处理灵感、作品集、分享、评审、摘要、历史等 | 后续按 Inspiration、WorkCollection、Share、Editorial 等用户用例拆分输入端口与服务 | 仅按行数拆类会保留耦合，还增加跨类跳转；应逐个业务迁移并验证 API |
| 中 | `CreativeWorkspaceRepository` 对应职责也较宽 | 与上述用例一起拆窄输出端口 | 只拆服务却保留万能仓储，边界并未改善 |
| 中 | `CommentApplicationService` 同时负责上下文构建、摘要、审计和审核 | 提取摘要协调与上下文查询，保留审核规则在领域 | 需要先固定现有上下文与生成行为的测试契约 |
| 中 | 评论列表逐条加载作者，可能形成 N+1 查询 | 批量读取作者或专用联表读投影 | 要用真实查询次数与数据量验证收益，不能只凭类名改 SQL |
| 中 | 模型运行期间文章、角色或自动订阅资格可能变化 | 明确“用准备快照生成”与“完成前必须再验证”的产品语义，再补 CAS/锁与测试 | 不能把已经有摘要版本验证误写成所有生成结果都有版本验证 |
| 低 | 部分派生摘要状态、跨内容修订投影仍以 String 表达 | 接口外观兼容下引入必要的枚举或值对象 | 读投影不一定需要一套完整富聚合；先确认字符串是否承载规则 |
| 低 | 少量手工结构映射和一些较大的 DTO 容器 | 触碰边界时渐进迁移 MapStruct | 一次性改全仓映射会放大低收益风险 |

## 从“代码的艺术”看

好代码应让业务意图沿着一条明确路径展开：入口说“我要做什么”，用例说“先后协调谁”，领域对象说“什么是合法的”，适配器说“用哪种技术完成”。`publishComment` 比 `transition(..., true)` 更易读；但为了凑齐 DDD 图里的每种模式而添加空壳服务，也会降低可读性。

因此目前不建议上微服务、消息总线、统一大 Common 模块或事件溯源。等到跨业务发布频繁互相影响、吞吐确实需要独立扩容、或团队有明确的上下文归属，再引入相应复杂度。SQL 计数这样的读模型可以保持简单。

文档与中文注释不能替代测试。本次并发测试验证任务确实运行在虚拟线程上、任务重叠、容量限制、异常及中断后的额度恢复；HTTP 测试验证匿名采集幂等、管理员排除和会员拒绝。真实模型的价格、速度与供应商限流还取决于部署配置，测试中使用模型替身，不会付费调用。
