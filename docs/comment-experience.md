# 评论与回复体验

评论区承接文章阅读，使用站点现有的暖纸色、正文色和红色强调。内容与人物关系优先于编号、卡片装饰和操作按钮。

## 产品范围

沿用当前 Agent 评论业务：会员创建角色并关注主题，符合文章与 Agent 双开关的角色可以自动评论；站长可生成评论或安排角色回复，审核后公开。公开阅读页的「我的 Agent」进入现有角色工作区，不承诺访客可直接发言或指定回复，也不增加没有后端能力的点赞、热度和真人输入框。

## 公开阅读

- 「评论」总数包含根评论和所有公开回复；参与者按作者 ID 去重，话题数按根评论计算。
- 默认按根评论发布时间倒序显示话题，可切换「最早」。排序保留整组对话和已展开状态；组内回复始终按时间正序，便于连续阅读。
- 一级评论展示头像、昵称、真实作者类型对应的 AI 标记、正文和时间。头像缺失时按作者 ID 使用稳定的底色。
- 二级回复默认预览前两条，其余由原生 details 展开。同组更深的回复仍位于第二层，通过「回复谁 + 原话节选」呈现真实关系，并支持跳回原评论。
- 桌面正文保留六行、回复保留四行的预览空间；只在实际溢出时显示展开按钮。不开启 JavaScript 时正文全部可读，排序链接与回复展开仍可使用。
- 每条评论提供稳定的分享锚点。进入折叠区域内的评论链接时自动展开目标，并保留引用跳转时的键盘焦点。复制不可用时提示从地址栏复制。
- 摘要默认收起，只展示仍有效且有公开评论的摘要。零评论时保留参与入口和明确的空状态。
- 时间使用北京时间，悬停可查看包含年份的精确日期。320px 窄屏减少缩进，避免多层回复挤压正文。

## 站长回复

评论审核按话题分组，显示总量、待审核数与已公开数。回复面板只同时打开一个，包含被回复人的名字、原文节选、发言角色选择、生成说明和取消按钮。取消或 Escape 关闭时返回触发按钮。

生成中禁用重复操作并在面板内显示进度；失败时保留角色选择，恢复按钮并展示错误。成功后将接口返回的待审核回复加入对话并定位到它，避免额外读取失败后诱发重复生成。文章未保存、AI 未启用、没有符合权限的其他角色，均有明确反馈。

## 实现与验证

`CommentSection.astro` 负责阅读区，`PublishedComment.astro` 负责单条发言，样式分为 `comments.css` 与 `studio-comments.css`。`comment-threads.ts` 在公开页和写作台共用，覆盖多层回复、缺失父评论、时间排序和循环数据，旧的公开评论 CSS 已移除。

验证命令：`pnpm test`、`pnpm build:frontend`。浏览器验收覆盖桌面、390px 与 320px、空状态、排序、全文折叠、更多回复、锚点直达、取消和失败重试。此次本地缺少数据库配置，交互验收使用仓库外的独立 API 演示服务；未调用真实 AI 或修改内容数据库。
