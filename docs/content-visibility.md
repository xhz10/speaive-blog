# 文章可见性与私密写作

## 业务理解

博客的内容状态和阅读权限是两件不同的事：

- `DRAFT` / `PUBLISHED` 描述文章是否仍在编辑、是否已经定稿；
- `PUBLIC` / `ADMIN_ONLY` 描述谁能读取文章。

因此“已发布”不再等于“已经对全网公开”。一篇文章可以处于 `PUBLISHED + ADMIN_ONLY`：它已经写完，但只有登录后的管理员能读。

| 内容状态 | 可见性 | 公开站 | 管理员写作台 |
| --- | --- | --- | --- |
| 草稿 | 公开 | 不可见 | 可编辑、可预览 |
| 草稿 | 仅管理员 | 不可见 | 可编辑、可预览 |
| 已发布 | 公开 | 首页、归档、详情、RSS、Sitemap 可见 | 可编辑、可预览 |
| 已发布 | 仅管理员 | 完全不可见，详情返回 404 | 可编辑、可在管理员阅读页查看 |

归档仍然是生命周期终点：归档后活动文章被移除，但修订快照保留。

## 本次决策

### 只引入两档权限

- `PUBLIC`：所有访客都可以读取；
- `ADMIN_ONLY`：只有现有管理员 Session 可以读取。

现有文章在数据库迁移后保持 `PUBLIC`，避免升级时意外隐藏整个历史博客。新建文章、网页上传 Markdown 和服务器投递箱导入默认使用 `ADMIN_ONLY`，防止新内容误发布。

### 暂不引入访客注册

当前需求是“给所有人看”或“只给自己看”，现有单管理员账号已经能完整表达这两种权限。现在增加注册会同时引入用户状态、邀请码、密码重置、会话撤销、账号停用和文章授权关系，但不会给当前业务增加实际能力，所以暂缓。

如果以后出现“只分享给几位指定读者”的需求，再新增第三档受邀可见。届时必须满足：

- 只有管理员可以生成邀请码；
- 邀请码随机、限时、可撤销，并默认只能使用一次；
- 服务端只保存邀请码摘要，不保存明文；
- 注册只需要用户名和密码，不绑定手机号；
- 文章权限关联稳定的用户 ID，不依赖可修改的用户名；
- 管理员可以停用账号并使其现有 Session 失效；
- 未匹配到明确授权时默认拒绝访问。

## 请求与数据边界

### 文章

`blog_post.visibility` 保存当前可见性，`blog_post_revision.visibility` 将每次可见性变化写入修订快照。公开列表和公开详情都在 SQL 查询层同时限制：

```text
status = PUBLISHED AND visibility = PUBLIC
```

所以私密文章不会进入首页、归档、RSS、Sitemap，也不能通过猜测 `/blog/{slug}` 读取。公开接口对“私密文章”和“不存在的文章”都返回 404，避免泄露 slug 是否存在。

### 图片

只隐藏正文是不够的；私密文章中的图片也必须受保护。

`blog_post_media` 记录文章实际引用的已上传媒体。匿名 `/media/**` 只有在媒体至少被一篇 `PUBLISHED + PUBLIC` 文章引用时才返回内容。其他媒体只能通过需要管理员 Session 的 `/api/v1/studio/media/**` 读取。

Studio 的编辑预览和管理员阅读页会把正文图片地址改写到受保护的媒体地址。Markdown 正文和封面仍保存规范的 `/media/**` 地址，之后把文章改为公开时不需要重写内容。

媒体响应使用 `Cache-Control: no-store`，避免浏览器持久缓存并确保从公开改回私密后，后续请求重新经过服务端授权判断。已经公开过的内容仍可能被访问者保存、截图或复制，应用无法撤回这些外部副本。

## 使用方式

1. 进入 `/studio/new` 或打开已有文章。
2. 在“谁可以看”中选择“仅自己（管理员）”或“所有访客”。
3. 保存或发布。私密文章发布后仍不会出现在公开博客。
4. 在写作台点击查看按钮，可进入受保护的 `/studio/read/{slug}` 阅读页。

Markdown frontmatter 也支持：

```yaml
visibility: ADMIN_ONLY
```

可用值只有 `ADMIN_ONLY` 和 `PUBLIC`。缺省时按仅管理员处理。

## 安全边界

“仅管理员”是应用层访问控制，适合保存不希望普通访客、搜索引擎或猜链接者看到的私人文字。它不是端到端加密或零知识存储：

- 能读取 PostgreSQL、服务器数据目录或完整备份的人仍能读取内容；
- 主机、管理员密码或管理员 Session 被攻破时，私密内容也会暴露；
- 不应把账号密码、API 密钥、助记词等高价值凭据写进博客；
- 生产环境必须使用 HTTPS、安全 Cookie、强管理员密码和受限备份权限。

访问控制采用默认拒绝和逐请求校验原则，参考 [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) 与 [Spring Security 请求授权文档](https://docs.spring.io/spring-security/reference/servlet/authorization/authorize-http-requests.html)。

## 迁移与回滚考虑

生产分支已经存在作者迁移 `V2` 和描述修复迁移 `V3`。本次按照 Flyway 只追加、不改写历史的原则新增 `V4__Add_post_visibility_and_media_access`，从而不会与服务器的迁移历史冲突：

- 为活动文章和修订快照增加 `visibility`；
- 将历史文章和历史修订回填为 `PUBLIC`；
- 创建文章与媒体引用关系，并从历史正文、封面中回填现有媒体；
- 将新记录的数据库缺省值设置为 `ADMIN_ONLY`。

部署前仍应先执行完整备份。Flyway 迁移只向前执行；需要回退应用版本时，应同时恢复升级前数据库备份，不能仅替换旧应用镜像。

## 实现过程与验收范围

本次变更先以服务器分支 `origin/docs/deployment-ops-notes` 为生产基线接入 `main` 历史，再依次完成业务状态拆分、V4 数据库迁移、四模块后端适配、持久化查询、媒体授权、Studio 编辑与阅读界面、自动化测试和文档更新。

自动化验收覆盖：

- 从生产的 `V1 -> V2 -> V3` 数据升级到 `V4` 时，活动文章和仅剩修订的归档历史保持公开，媒体引用正确回填；
- 私密已发布文章不出现在公开列表，公开详情返回 404；
- 管理员仍可读取、编辑和预览私密文章；
- 未关联媒体和私密文章媒体不能匿名读取；
- 私密文章改为公开后正文与图片可读，改回私密后再次拒绝；
- Markdown 导入默认仅管理员；
- 可见性修改继续受 revision CAS 保护；
- Astro 类型检查、前端代理测试、后端单元与 PostgreSQL 集成测试。
