# 创作闭环升级

## 目标

这次升级把博客从“发布文章的后台”推进为一套个人创作工作区。完整链路是：

1. 用灵感收件箱快速捕捉一句话、场景、人物、对话或问题。
2. 在文章或小说写作台持续修改，并能查看、比较和恢复服务端历史版本。
3. 用作品集把文章与小说片段编排成有顺序的阅读路径。
4. 在发布前让已审核 Agent 提供仅管理员可见的编辑意见。
5. 将公开评论压缩成一份可展开的圆桌摘要，完整评论仍然保留。
6. 用标签和时间让旧文章、长期未续写的小说片段重新回到写作台。
7. 用可过期、可撤销的随机链接临时分享原本不公开的内容。

## 三个决策维度

### 体验

- 捕捉灵感时只要求正文，标题可由第一行自动生成。
- 历史版本默认只展示时间、事件和摘要；需要时再展开正文或执行恢复。
- 作品集采用手动排序，公开页提供上一篇、下一篇和返回作品集入口。
- AI 编辑意见和圆桌完整发言默认折叠，先给结论，再给长文本。
- 临时分享页保持纯阅读体验，并明确显示过期时间。

### 成本

- 不复制文章或小说正文，作品集和分享只保存稳定引用。
- 历史版本复用现有 `blog_post_revision` 与 `blog_novel_fragment_revision`。
- 旧内容复活先采用标签、日期和更新时间，不引入向量检索。
- AI 编辑和圆桌摘要只由管理员手动触发，结果持久化；页面访问不会调用模型。
- 分享令牌只保存 SHA-256 摘要，数据库泄露时不能直接还原访问链接。

### 效率

- 灵感支持置顶、类型和状态，减少在草稿列表里寻找半句话的成本。
- 恢复历史版本会创建一个新的修订，不覆盖或删除过去记录。
- 作品集可同时收纳文章和小说片段，避免维护两套专题系统。
- 圆桌摘要通过评论指纹判断是否过期，只有评论改变时才需要重新生成。

## 领域与数据

### 灵感 `blog_inspiration`

- 类型：`IDEA`、`SCENE`、`DIALOGUE`、`CHARACTER`、`QUESTION`
- 状态：`INBOX`、`DEVELOPING`、`CONVERTED`、`ARCHIVED`
- 使用整数 revision 做 CAS 更新，防止多个页面互相覆盖。

### 作品集 `blog_work_collection` / `blog_work_collection_item`

- 作品集拥有 slug、标题、简介、封面、可见性和 revision。
- 条目只保存 `POST` 或 `NOVEL` 与内容 slug，不复制正文。
- 公开读取时再次校验条目自身确实为已发布且公开；作品集公开不能绕过内容权限。

### 历史版本

- 新增只读查询适配器读取现有修订表。
- 恢复只恢复正文元数据和可见性，保留当前发布/草稿状态，避免一次恢复意外公开内容。
- 恢复本身记录为 `RESTORE` 修订事件。

### 临时分享 `blog_share_grant`

- 支持文章和小说片段。
- 原始令牌只在创建响应中返回一次；数据库仅保存哈希。
- 访问时检查撤销时间和过期时间，公开接口不可枚举。
- 分享页使用 `noindex`，但分享链接仍应视为持有者可访问的秘密，而不是强身份认证。

### 私密编辑意见 `blog_editorial_review`

- 绑定文章 ID、文章 revision、Agent 和可选的原文引用。
- 只存在于写作台接口，永不进入公开评论接口。
- 文章更新后旧意见仍可查看，但会标记为针对旧 revision。

### 圆桌摘要 `blog_discussion_digest`

- 绑定文章 ID、文章 revision 和已发布评论指纹。
- 摘要缓存只在指纹匹配时对外展示；评论发布、隐藏或回复后自动表现为过期。

## HTTP 边界

- `/api/v1/studio/creative/inspirations/**`：灵感管理。
- `/api/v1/studio/creative/works/**`：作品集管理。
- `/api/v1/public/works/**`：公开作品集与连续阅读导航；导航接受 `workSlug`，同一内容被多套作品收录时仍保持当前阅读路径。
- `/api/v1/studio/creative/{type}/{slug}/revisions/**`：版本历史与恢复。
- `/api/v1/studio/creative/shares/**`：创建、查看和撤销临时分享。
- `/api/v1/public/shares/{token}`：解析有效分享。
- `/api/v1/studio/creative/posts/{slug}/reviews/**`：生成和读取私密编辑意见。
- `/api/v1/studio/creative/posts/{slug}/discussion-digest`：手动生成圆桌摘要。
- `/api/v1/public/posts/{slug}/discussion-digest`：读取仍有效的公开摘要。
- `/api/v1/studio/creative/resurfacing`：读取无模型成本的旧内容建议。

## 安全约束

- Studio 写操作继续使用管理员 Session 与 CSRF。
- 公开分享解析是唯一新增的匿名内容读取入口，只接受高熵令牌。
- 令牌创建限制有效期为 1 到 90 天，并支持立即撤销。
- `ADMIN_ONLY` 内容只能交给 `canProcessPrivate=true` 的 Agent。
- 文章正文、评论和选中文本都作为不可信模型输入，不执行其中的指令。

## 管理员操作路径

- `/studio/creative/`：随手记录灵感，修改类型、置顶和状态；转换成文章或小说后可保存目标链接。
- `/studio/works/`：创建作品集，把已存在的文章或小说片段按阅读顺序加入，并决定作品集是否公开。
- 文章或小说编辑页底部：展开时间机查看/恢复版本，或生成一次性私密分享链接。
- 文章编辑页底部：选择 Agent 审阅全文或正文选区；评论达到两条后手动整理圆桌摘要。
- `/works/`：访客浏览公开作品集；作品详情与文章/小说详情互相提供连续阅读入口。

## 实现与验收记录

实现继续遵循现有模块化单体边界：`domain` 保存灵感、作品集和授权的不变量，`application` 编排权限、恢复、AI 与旧内容建议，`infrastructure` 负责 PostgreSQL、Flyway 和 Spring AI，`start` 只承接 HTTP 与 Bean 装配，Astro 负责写作和阅读体验。

关键验收覆盖：

- 未登录用户不能读取或修改创作工作区；写请求必须通过 CSRF。
- 恢复历史不会删除当前版本，而是新增 `RESTORE` 事件并保留当前发布状态。
- 私密内容不进入公开文章接口，但有效分享令牌可以只读访问；撤销或过期后立即返回 404。
- 数据库只保存分享令牌 SHA-256 摘要，原始令牌仅创建时返回一次。
- 公开作品集会再次过滤私密、草稿或已撤回条目，连续阅读自动跳过它们。
- AI 只由管理员手动触发，私密编辑意见永不进入公开评论，圆桌摘要过期后不向访客展示旧正文。
- 前端类型检查、组件测试、SSR 生产构建、Java 单元/架构测试、Flyway 与 PostgreSQL Testcontainers 集成测试全部纳入验收。

## 部署

不需要新增部署脚本或环境变量。服务器在 `main` 拉取代码后继续执行：

```bash
./scripts/docker-up.sh
```

镜像重建后 Flyway 自动执行 `V9__Add_creative_workspace.sql`。如果没有启用 AI，其余灵感、版本、作品集、分享和旧内容建议仍可正常使用；私密编辑与圆桌摘要会明确提示 AI 未配置。备份脚本无需修改，因为新增数据都位于现有 PostgreSQL 数据库中。
