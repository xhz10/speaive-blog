# 博客界面与交互评审

这轮设计围绕一个判断：读者应该轻松找到文字，作者应该安心地写。视觉沿用米白纸色、衬线标题和朱红点缀，再用原创配图建立辨识度。

## 如何判断一个博客设计得好不好

不用先学设计术语，可以直接检查四件事：

1. **进来知道读什么**：首页先说明内容气质，让最近文章容易被找到。
2. **操作前知道后果**：保存、公开发布、撤回、归档，各自的结果要清楚。
3. **操作后知道状态**：写了但没保存、保存成功、连接失败，不能看起来一样。
4. **手机上用起来舒服**：导航能看全、按钮容易点、正文不横向溢出。

## 当前判断与这轮落地

| 方面 | 原来的问题 | 本轮实现 |
| --- | --- | --- |
| 视觉气质 | 有不错的留白与字形，但长期依赖单张钢笔图片 | 新增纸鸟静物主视觉和窗边书桌插画，分别服务阅读与写作入口 |
| 首页层级 | 介绍后缺少明确的阅读动作 | 增加“从最近一篇读起”；最近文章紧接主视觉；写作邀请放在内容之后 |
| 导航 | 阅读、Agent 和写作入口同等突出，手机需要横向找入口 | 公共导航提供文章、小说、作品与朋友等阅读入口；“我的写作”独立；Agent 仍可从页脚及写作区进入 |
| 文章列表 | 卡片有整行悬浮反馈，只有标题能点 | 标题链接覆盖整行，标签保留独立点击与键盘焦点 |
| 写作预览 | 必须先保存，才能预览 | 新增经过认证、CSRF 和 HTML 清洗的预览接口；预览不创建文章或修订 |
| 保存反馈 | 成功、等待与错误使用相近的提示 | 分别呈现处理中、成功、错误；工具栏保持可见；已公开文章明确标为“更新公开文章” |
| 发布与归档 | 原生浏览器确认框缺少层级和具体动作名称 | 使用页面内原生 dialog，描述后果，取消默认获得焦点，支持 Esc 与关闭后返回触发按钮 |
| 表单校验 | 先禁用控件，再调用校验，浏览器可能跳过必填检查 | 在锁定输入前校验；预览允许尚未起标题，不会强迫先保存 |
| 加载失败 | 首页接口异常可能落入框架错误页 | 首页保留导航与页面结构，显示加载失败和重试，返回 503，不伪装成“还没有文章” |

## 两张图片如何使用

- **日光与纸页**：纸鸟、红色书脊、自然窗光。用于首页主视觉，不套用到每一篇内容上。
- **留一盏写作的灯**：夜色、笔记本、台灯。用于首页写作邀请和会员登录，表达可以安静写作的氛围。
- 文件位于 `public/images/editorial/`，每张提供 480、960、1536 三个宽度的 WebP。组件使用 `srcset`、`sizes`、明确宽高；首页首图优先加载，页面下方插画延迟加载。
- 这两张是 AI 生成的原创视觉素材，不是作者真实书房照片。现有文章封面保持不变，避免替内容制造不相干的配图。

## 关键交互依据

禁用的表单控件不参与浏览器约束校验，因此必须先校验，再禁用。参见 [MDN disabled 属性说明](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/disabled)。

确认窗口使用原生 `dialog`，保留模态焦点、Esc 退出，并在关闭后返回原触发位置；操作后果写在按钮之前。参见 [W3C 原生 dialog 技术说明](https://www.w3.org/WAI/WCAG21/Techniques/html/H102)。

## 后续值得继续做的事情

1. **公开作者发现**：已完成“朋友的文字”与首页公开作品入口，见 [作者体验目标](experience-goals.md)。后续可完善作者自我介绍，只有私密草稿的账号不进入公开发现列表。
2. **归档找回**：已完成归档筛选与找回；找回时恢复为私密草稿，保留内容、历史与加密。后续可考虑历史版本的差异对比。
3. **跨页样式整理**：现有全局样式和多轮补充样式较多。后续可按导航、文章列表、表单、对话框等组件逐步收拢，避免继续叠加大范围覆盖。
4. **实际读者反馈**：可以请一位首次访问的朋友完成“找一篇文章”和“保存一篇草稿”，观察哪里犹豫，再决定下一轮优先级。

本轮没有改变会员加密范围和发布权限，也没有把私密预览发送给 AI。预览只调用现有的后端 Markdown 清洗与渲染能力。

## 本轮验收记录（2026-09-12）

- 后端 `./mvnw clean verify`：133 项测试通过，包含真实 PostgreSQL 集成测试、打包运行与架构规则；预览接口覆盖认证、作者权限、CSRF、脚本清洗、禁止缓存以及不增加文章或历史版本。
- 前端 `pnpm test`：46 项测试通过；`pnpm run check` 无错误、警告或提示；`pnpm run build:frontend` 通过。
- 浏览器使用独立本地数据库和演示账号，验证桌面与手机首页、图片加载、作者登录、空标题拦截、未保存预览、保存、发布取消与确认、历史恢复取消、未保存退出取消与确认。
- 手机首页与编辑器未出现横向溢出；确认窗口默认聚焦取消，Esc 关闭后焦点回到触发按钮。
- 实测修复了手机工具栏拥挤、辅助标签意外显示，以及退出确认等待结束后事件对象失效的问题。
