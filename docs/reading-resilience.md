# 公开阅读页的加载容错

正文、评论、讨论摘要和作品集导航各有自己的失败状态。文章已经正常读取时，后面任何一项失败都不能让整篇文章变成错误页；接口故障也不能伪装成“还没有评论”。

## 页面行为

| 请求结果 | 页面结果 |
| --- | --- |
| 正文正常，附属内容正常 | 完整正文、正常评论与导航 |
| 评论失败 | 正文保留，评论显示“暂时没能加载”及重试；不显示虚假的 0 条评论 |
| 摘要失败 | 正常评论继续显示，摘要单独提示 |
| 作品集导航失败 | 正文和评论保留，导航提供重试说明 |
| 正文返回 404 | 404 页面，说明不存在或未公开 |
| 正文请求失败或超时 | 503 页面，提供重新加载；不伪装成不存在 |

正文读取成功后，附属请求并行执行，各自等待最多 3 秒。公开主请求最多等待 8 秒，避免无限等连接。页面禁止缓存，防止短暂失败或刚撤回的内容停留在共享缓存中。小说片段使用同样的正文与导航边界；朋友文章原有的 404/503 提示继续保留。

重试按钮通过 GET 表单重新请求页面，保留作品集和评论排序等查询参数；评论重试后仍定位到评论区。表单每次渲染带有新的重试标识，即使当前已在 `#comments`，也会真正发起请求，关闭 JavaScript 后仍可使用。

## 代码与验证

- `src/lib/reading-page.ts` 协调必需正文及可独立降级的附属请求。
- `src/lib/public-api.ts` 保留错误与不存在的区别，设置请求截止时间。
- `CommentSection.astro` 区分空评论与不可用，不展示异常堆栈。
- `tests/reading-page.test.ts` 覆盖主内容状态、评论/摘要/导航独立失败、并行请求，以及小说阅读。

浏览器故障验收使用独立的合成 API，不停止实际博客服务，也不修改生产内容。

## 验收记录（2026-10-11）

真实 Chrome 完成 9 项故障场景：评论、摘要、导航与响应正文超时分别降级，文章 404/503 状态区分，小说导航故障保留正文，同锚点重试恢复评论，切换评论排序后重试保留当前排序，以及关闭 JavaScript 后通过原生表单重试。手机宽度没有页面横向溢出，浏览器脚本未报异常。

超时验证同时涵盖响应头已返回但 JSON 正文未结束的情况，附属内容约 3 秒后结束等待。实际页面见 [评论故障时的手机阅读页](design/screenshots/reading-resilience-mobile.jpg)。
